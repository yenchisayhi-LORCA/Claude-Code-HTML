# 🌟 小孩獎勵紀錄本

純前端（HTML/CSS/JavaScript，無框架、無建置流程）的小孩獎勵紀錄工具，資料儲存在瀏覽器 localStorage，不需要後端伺服器或帳號登入。跟同一個 repo 裡的「旅遊記帳系統」是完全獨立的小工具，只是放在同一個專案裡。

## 功能

- **多小孩支援**：每個小孩獨立姓名、大頭貼、星星紀錄，畫面上方可以隨時切換。
- **完成作業給星星**：家長預先設定作業清單（名稱／圖示／星星數），小孩完成後點一下就自動入帳（同一項作業同一天只能算一次）。
- **手動調整星星**：任何沒有列在清單裡的表現，也可以手動加減星星並填原因（需要 PIN）。
- **運動自主回報**：小孩自己回報走路步數、開合跳次數等實際數字，依家長設定的換算比例自動算出建議星星數（無條件捨去，例如每 9000 步 = 1 顆星），家長審核（可調整）通過後才正式入帳。
- **星星帳本**：星星不是只增不減，所有加減紀錄都是一筆一筆的帳本，可以在星星商店把星星換成實體禮物、現金或特權。
- **獎狀牆**：家長可以設定多層星星門檻，小孩的星星餘額每次由下往上跨過某個門檻，就會自動解鎖一張新獎狀（同一個門檻可以因為餘額起伏被重複解鎖）；獎狀可以放上傳的小孩專屬照片，能下載 PNG 或直接列印，所有曾經解鎖過的獎狀都會留在獎狀牆裡。
- **儲蓄挑戰**：家長可以自訂「維持最低餘額＋連續天數」的儲蓄挑戰，達成就發一筆額外的獎勵星星，然後自動重置繼續挑戰下一輪，鼓勵存錢而不是馬上花光。
- **打卡日曆 + 連續天數**：月曆檢視哪幾天有完成任務／運動紀錄，並顯示目前連續天數搭配火焰徽章；加星星、解鎖獎狀時會有彩帶/星星慶祝動畫。
- **家長 PIN 保護**：可設定 4 位數 PIN，設定後編輯作業清單/運動公式/獎狀門檻/儲蓄挑戰/商店品項、手動調整星星、審核運動回報、商店兌換、刪除小孩都需要輸入 PIN。這只是給小孩用的軟性門檻，不是真正的安全機制（PIN 是明碼儲存）。
- **多裝置同步（選用）**：設定好 Firebase 後，可用 Email 登入（收信點連結，不用密碼），讓同一個帳號在手機、平板等不同裝置間即時同步（例如爸媽在手機上調整星星，小孩在自己的平板上看到最新餘額，或自己回報運動數字）。沒設定的話完全不影響其他功能，資料就只存在本機。

## 如何執行

跟根目錄的旅遊記帳系統一樣，需要透過本機伺服器開啟：

```bash
python3 -m http.server 8080
```

然後用瀏覽器開啟 `http://localhost:8080/kids-reward-tracker/`。

## 部署

純靜態網頁，可以直接跟根目錄的旅遊記帳系統一起部署到 GitHub Pages、Netlify、Vercel 等靜態代管服務，不需要任何後端設定。

## 資料儲存與限制

- 所有資料預設存在瀏覽器的 `localStorage`，**只存在於目前這個瀏覽器/裝置**，換瀏覽器或清除瀏覽器資料會遺失紀錄。設定好雲端同步（見下方）後，同一個帳號的資料會額外保存一份在 Firestore，換裝置登入就能拿回來、即時同步。
- 儲蓄挑戰的「連續天數」是簡化版邏輯：只要每天有打開 app 且餘額達標就算一天，不是嚴格回溯每天午夜的歷史餘額快照。
- 獎狀門檻的判斷基準是「目前星星餘額」，每次餘額由下往上重新跨過同一個門檻都會再解鎖一次獎狀，即使中間曾經把星星花完。
- localStorage 通常有 5MB 左右的容量限制，大頭貼與獎狀照片都會自動壓縮，但累積很多獎狀後仍建議留意空間；雲端同步的 Firestore 單一文件也有約 1MB 上限，照片太多可能導致同步失敗（本機資料不受影響，畫面上會顯示同步失敗的提示）。

## 設定多裝置同步（選用）

這個功能**直接沿用根目錄旅遊記帳系統已經設定好的同一個 Firebase 專案**，不需要另外申請新專案；如果你已經照根目錄 README 的步驟設定過旅遊記帳系統的雲端同步，這裡只差一步——把下面這段規則加進 Firebase Console 的 Firestore 規則：

1. 打開 [Firebase Console](https://console.firebase.google.com/) → 選你原本那個專案 → **Build → Firestore Database → 規則（Rules）**分頁。
2. 在既有規則的 `match /databases/{database}/documents { ... }` 區塊裡，**新增**（不要刪掉原本 `users`/`shared_trips` 那兩段）：
   ```
   match /kids_reward_users/{userId} {
     allow read, write: if request.auth != null && request.auth.uid == userId;
   }
   ```
3. 發布規則。

設定完成後，重新整理網頁，右上角會出現「☁️ 登入同步」按鈕：手機、平板都輸入**同一個** Email、收信點連結登入，資料就會即時同步——例如爸媽在手機上完成任務給星星，小孩平板上的餘額會自動更新，不用手動重新整理。

因為是同一個 Firebase 專案、同一套登入機制，如果這台裝置的瀏覽器已經在旅遊記帳系統登入過同一個 Email，打開這個 app 時通常會直接自動是登入狀態，不用再收一次信。資料本身寫在不同的 Firestore collection（`kids_reward_users`，跟旅遊記帳系統的 `users`/`shared_trips` 分開），兩邊資料不會互相干擾。

如果還沒設定過 Firebase（兩個 app 都還沒接雲端同步），請先照根目錄 README 的「設定多裝置同步」步驟建立 Firebase 專案、啟用 Email 連結登入、把設定值貼進 `js/firebase-config.js`，再回來加上面這段規則即可（這個 app 自己的 `kids-reward-tracker/js/firebase-config.js` 已經預先填好跟根目錄同一組設定值）。

## 專案結構

```
index.html          主頁面結構與所有彈窗（Dialog）
manifest.json        PWA 設定（加到主畫面時的名稱/圖示/顯示模式）
css/style.css        樣式（粉彩繽紛童趣風，跟根目錄旅遊記帳系統的沉穩風格完全獨立）
sw.js                 離線快取（scope 限定在這個子資料夾，不影響根目錄的旅遊記帳系統）
icons/                 加到主畫面用的 app 圖示（apple-touch-icon.png、icon-192.png、icon-512.png）
js/
  app.js             主要邏輯：畫面渲染、事件綁定
  storage.js          localStorage 資料存取（小孩/作業/帳本/門檻/挑戰/商店/PIN 的 CRUD）
  ledger.js            星星帳本核心：餘額計算、獎狀門檻跨越偵測、儲蓄挑戰進度、連續天數
  tasks.js              完成作業／手動調整星星
  exercise.js            運動回報的換算公式、送出、審核
  shop.js                星星商店兌換
  certificate.js          獎狀 canvas 繪製、PNG 匯出、列印
  calendar.js              月曆格與連續天數徽章的畫面渲染
  pin.js                    家長 PIN 設定/驗證/操作前置攔截
  image.js                   照片壓縮（大頭貼、獎狀照片）
  confetti.js                 星星/彩帶慶祝動畫
  icons.js                     作業/商店的 emoji 圖示選項
  cloud-sync.js                 多裝置同步（Firebase Auth + Firestore，選用，跟根目錄同一個專案不同 collection）
  firebase-config.js              雲端同步的 Firebase 設定值（已預填跟根目錄同一組）
```
