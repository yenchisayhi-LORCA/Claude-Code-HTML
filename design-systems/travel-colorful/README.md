## 內容基調

這是一個純前端、無框架、親切不正式的旅遊花費記帳工具，全繁體中文介面。文案用直接的口語句子（「設定完成後，重新整理網頁，右上角會出現『☁️ 登入同步』按鈕」），不用生硬的系統術語。按鈕與功能標籤固定用一個 emoji 當前綴當作功能性的小圖示，不是裝飾——`☁️ 登入同步`、`👤 管理成員`、`🔗 分享此旅程（唯讀）`、`🧳` 作為 App 本身的視覺標誌。新增文案時比照這個「emoji + 動詞片語」的格式，emoji 一律放最前面、只用一個。錯誤訊息要講清楚原因與下一步（例如「登入已取消：沒有取得 Email，這組登入連結已經失效，請重新點擊『登入同步』寄一次新的連結」），不要只寫「發生錯誤」。

## 色彩

只有一個主題（Light），沒有深色模式。頁面背景固定用 `app-bg`，四個背景裝飾圓點色塊分別取 `app-primary`、`app-teal`、`app-danger`、`app-warn`，有機地疊在畫面邊角，不要排成網格。所有卡片、面板、對話框底色一律用 `app-surface`（偏奶油白，不是純白），文字用 `app-text` / `app-text-muted` / `app-text-muted-2` 三階。四組功能色（`app-primary` 主色、`app-teal` 完成／成功、`app-danger` 危險／刪除、`app-warn` 提醒／超支）各自配一組 `-dark`（疊在 `app-surface` 上的文字顏色）與 `-tint`（淺底標籤、提示框背景），絕對不要直接拿飽和的基礎色當文字色用在白底上——`app-warn`（#F5B324）文字對比不夠，一律改用 `app-warn-dark`。

匯出圖卡與可列印報表走另一套稍暖、偏米色的配色，不沿用 App 介面的藍紫基底：整張底用 `export-bg`，卡片底用 `export-card`，邊框 `export-border`，文字用 `export-ink` / `export-text-muted` / `export-text-muted-2`，統計強調色用 `export-accent-orange`（總花費卡）與 `export-accent-teal`（建議轉帳卡）。

### 成員識別色（10 色）

花費明細、每人結算、建議轉帳三個地方都需要「同一個人永遠同一個顏色」：10 組 `member-*-text` / `member-*-bg` 依成員姓名算雜湊自動分配（不是用內部 id，因為同一個人在不同旅程裡的 id 不一樣；也不是每次匯出重新洗牌，同一個人要在任何時候、任何一趟旅程匯出都拿到同一個顏色）。`text` 疊在白色卡片上當姓名文字，`bg` 當建議轉帳頭像圓底、跟對應的 `text` 成對使用。前 4 組（indigo／teal／red／amber）直接是 App 四組功能色的 `-dark`／`-tint`；後 6 組（yellow／green／pink／lavender／lightblue／purple）原色偏亮或偏粉彩，`text` 版本是同色相調暗到跟白底、跟自己的 `bg` 圓底對比度都至少 4.5:1 算出來的，不要直接拿淺色當文字色。目前 `member-amber-text`／`member-amber-bg` 固定保留給特定成員「林小琪」、`member-pink-text`／`member-pink-bg` 固定給「范小芳」、`member-lightblue-text`／`member-lightblue-bg` 固定給「邱小芳」，新增鎖定對象時比照這個模式，其餘成員的自動分配要跳過已經被鎖定的顏色，不能撞色。

### 分類圖示徽章

9 個花費分類（交通／住宿／餐飲／票券門票／購物／娛樂／通訊網路／醫療／其他）各自一個底色徽章：`icon-transport-bg`、`icon-stay-bg`、`icon-food-bg`、`icon-ticket-bg`、`icon-shopping-bg`、`icon-entertainment-bg`、`icon-telecom-bg`、`icon-medical-bg`、`icon-other-bg`。圖示本身是手繪 SVG（不是圖示字型、不是 emoji），9 個都在 Icons 資產群組裡，每個都是獨立物件、2–5 個色塊堆疊出一個小場景（交通是車窗+輪子、住宿是屋頂+窗戶、餐飲是漢堡+吸管…），不是線條單色圖示。新增分類圖示比照這個「手繪色塊場景、26×26 viewBox」的畫法，直接用 Icons 群組裡的檔案當起點微調，不要換成圖示字型或簡化成單色線框。

## 文字

兩種字型家族疊在一起用：`display`（Baloo 2 + Noto Sans TC 後備）用在 App 介面的標題與按鈕——中文字會自動 fallback 到 Noto Sans TC，Baloo 2 只在拉丁字母／數字生效，是整個 App 唯一的「造型感」字體來源；`body`（Noto Sans TC）用在所有內文、花費列表、匯出圖卡的 canvas 繪字。可列印／存成 PDF 的報表另外用 `print`（Zen Maru Gothic + Noto Sans TC 後備），字感比匯出圖卡更圓潤柔和，是刻意跟螢幕上的匯出圖卡做出區隔的版本，只有開新分頁列印那條路徑會載入。所有標題、金額、按鈕文字一律用重字重（700–900），正文與次要資訊才用 400–600，不要讓次要文字跟標題同樣粗。

## 間距與圓角

間距從 `space-1`（6px）到 `space-9`（28px）九階，App 一般卡片內距用 `space-6`（16px），面板用 `space-7`（20px），最外層的旅程資訊卡用 `space-9`（28px）。圓角偏大、偏圓潤，是這個 App 「軟萌但好用」個性的主要來源：一般元件（按鈕、輸入框、花費列表卡片）用 `radius-md`（16px），大型卡片與對話框用 `radius-lg`（26px），匯出圖卡與可列印報表的小卡片用 `radius-card`（20px），圖示徽章用 `radius-sm`（15px），金額標籤與圓形頭像一律用 `radius-pill`（999px）畫成全圓角藥丸或正圓形。不要用小於 15px 的直角或微圓角，那不是這個系統的語彙。

## 陰影：無暈染的硬邊立體感

這是整個視覺系統最明顯的招牌特徵：所有陰影都是**純平移、零模糊**（`0 <偏移量>px 0 <顏色>`，沒有 blur radius），模擬紙板貼紙疊起來的厚度感，不是真實光線的柔和暈染陰影。卡片與面板用 `shadow-card`（偏移 10px）或 `shadow-panel-lg`（偏移 12px），顏色固定是半透明的深靛藍 `rgba(24, 32, 80, .18)`，不要換成黑色陰影。按鈕與其他小型凸起元件用更淺的偏移（`shadow-button-primary`、`shadow-button-warn` 等偏移 4px），顏色用該元件底色自己的 `-dark` 版本，不是統一的灰黑色——陰影色要跟著元件底色走，這樣每個按鈕才有自己的「立體感」而不是全部疊同一層灰霧。新增任何有高度層次的元件，一律比照「零模糊、顏色跟著底色的 -dark 版本走」這個規則，不要用瀏覽器預設的 `box-shadow: 0 2px 8px rgba(0,0,0,.1)` 這種真實光暈陰影。

## 匯出圖卡（PNG 圖片）與可列印報表

這兩個輸出都不是把畫面截圖，是各自用程式重畫一次同一份版面（匯出圖卡用 canvas 指令、可列印報表用一般網頁 HTML），因為瀏覽器對截圖/SVG foreignObject 轉 canvas 有限制。匯出圖卡拆成「總覽」（總花費＋每人結算＋建議轉帳）跟「明細」（花費清單）兩張各自獨立下載的圖片，各自都要有完整的頁首（App 標誌＋旅程標題）跟頁尾，單獨看任何一張都看得出是哪趟旅程。版面數字（間距、字級、圓角、顏色）要跟可列印報表的網頁版對照得起來，不是各自隨意決定；需要跟設計稿完全一致的字型時才走「列印/存成 PDF」那條路（能安全載入 Google Fonts 的網頁渲染），canvas 版本受限於字型載入時機，固定只用 Noto Sans TC。

## Excel／CSV 匯出：純資料表，不做視覺樣式

Excel (.xlsx) 跟 CSV 匯出是純數據表格——表頭＋一列一筆花費，數字欄位維持 number 型別方便使用者自己在 Excel 裡加總，不套用任何儲存格底色、字型或框線樣式。這是刻意的：匯出圖卡負責「好看、適合分享」，Excel/CSV 負責「好算、適合匯入其他工具」，兩者分工不重疊。新增匯出欄位時維持這個「純資料、零樣式」的原則，不要為了好看反而讓使用者不能直接 SUM() 整欄。

## 版面語彙

整體版面偏向「卡片堆疊」：大圓角卡片疊加半透明深靛藍硬邊陰影，彼此之間用 `space-6`〜`space-9` 的間距隔開，不做邊框分隔線式的扁平表格版面。圓形或藥丸形狀的頭像／標籤／按鈕角色一致：凡是「代表一個人」（成員頭像）或「代表一個最終數字」（金額、總額）的元件都用 `radius-pill` 收尾，凡是「容器」（卡片、面板、輸入框）都用 `radius-md`／`radius-lg`／`radius-card`，不要混用。
